# 功能演示

[English](DEMO.md) | **简体中文** · [返回中文 README](README.zh-CN.md)

以下截图于 2026-09-26 拍摄，使用 **Deepseedian 0.7.1、macOS Obsidian 1.13.7**。笔记是专门编写的合成演示资料，回答来自真实 `deepseek-official / deepseek-flash` 请求，不含私人文章。输出和耗时仅代表这次演示，界面当前以中文为主。

## 准备演示库

先完成[安装与连接](README.zh-CN.md#安装与环境)，再把 [demo-notes](demo-notes) 中的内容复制到独立测试库，保留 `演示/` 和 `notes/` 的目录结构。不需要复制任何 `.obsidian` 文件夹或凭据。发送问题会产生实际模型请求与可能的费用；查看上下文、创建分支和生成目录本身不调用模型。

## 1. 把笔记变成行动卡

打开[从读懂到讲清楚](demo-notes/演示/从读懂到讲清楚.md)，在 Markdown 编辑器中选中需要解释的全文或段落，使用“向 Deepseedian 提问”。发送前打开“查看下次发送的上下文”核对范围。普通当前笔记默认取光标附近内容，并不等于附带全文；需要特定范围时请明确选中。

截图使用的问题：

> 根据这篇笔记，帮我做一张简短的学习行动卡：一个目标、三个步骤、一个自检问题。只使用当前笔记，不调用工具或保存记忆。

回答给出源于笔记的目标、步骤与自检问题，原文没有被改写。回答下方显示供应商返回的 token 用量和缓存信息。

![笔记问答与真实行动卡](screenshots/chat-0.7.1.png)

## 2. 发送前检查上下文

点击“查看下次发送的上下文”，展开当前笔记，核对路径、选区或附近段落、历史消息数与记忆状态。可以在这里停止附带当前笔记，或修改本会话的记忆读取权限。

这是一份预览，不是模型全部输入的完整重放；移除来源不会清除已发送历史中的内容。下图是在后续操作中重新捕获的光标附近片段，比生成行动卡时选中的全文更短。

![上下文与记忆状态检查](screenshots/context-0.7.1.png)

## 3. 从一轮回答创建分支

点击已完成回答下方的“分支到新聊天”。新会话继承截至这轮的历史，顶部显示来源和“返回原对话”，可以从这里追问另一条思路。

创建分支本身不调用模型，后续提问仍按供应商计费。分支隔离聊天历史，但笔记和本库记忆仍共享，不自动合并或回传结论。本轮验收还单独验证了重载 Obsidian 后恢复分支。

未发布变更：新分支使用 `原标题（1）`、`原标题（2）` 等编号后缀，从分支继续分支时也按同一标题编号。已有会话标题保留；下图记录的仍是正式 0.7.1 的标题格式。

![独立会话分支及来源入口](screenshots/fork-0.7.1.png)

## 4. 看清模型实际调用了什么

在父会话中继续提问：

> 请只通过只读笔记工具读取「演示/学习复盘.md」，用两句话说明下一次学习应做什么，并给出笔记引用。不要联网，也不要写入记忆或修改文件。

切换到“轨迹”，选择“调用”，展开工具请求与返回结果。本次真实运行调用了 `obsidian_read`，参数指向演示笔记，结果包含带行号的原文；最终回答也给出了该笔记引用。还可以切换“时长”“轮次”，或使用搜索框筛选事件。

![真实只读工具调用的参数与返回结果](screenshots/trace-0.7.1.png)

轨迹按宿主接收时间排列，总跨度可能包含两次提问之间的空闲时间，不能当作单次回答耗时。轨迹可以帮助核对来源，但不保证模型理解正确。

## 5. 在本地预览文章目录

输入 `/catalog`，或运行“整理文章目录”命令。文章目录填 `notes`，输出目录使用尚不存在的 `_目录演示`，点击“扫描并预览”。示例文章具备支持的属性，图中显示扫描到 1 篇且无缺失属性。

![创建前的本地目录预览](screenshots/catalog-0.7.1.png)

可以展开 Base 与导航文本检查内容。只有点击“确认新建两个文件”才会写入 `文章管理.base` 和 `文章导航.md`；直接关闭预览不会创建文件。启用 Obsidian 核心插件 Bases 后可打开表格。此流程不调用模型，也不修改原文章。

## 6. 试用手动补全

该功能默认关闭，固定使用付费 `deepseek-official / deepseek-flash`，与聊天模型独立。在插件设置中启用后，将光标放在 Markdown 正文中，运行“请求当前位置补全”；**Tab** 接受，**Esc** 取消，接受后可独立撤销。

本次文档更新没有重新拍摄补全或新增补全质量结论。行为与限制见[补全说明](TAB-COMPLETION.md)，实际成功和失败样例见 [0.7.0 验证记录](VALIDATION-0.7.0.md)。
