# 手动笔记补全

手动补全已合并到主分支，并作为 Deepseedian 0.7 的正式功能提供。默认关闭，启用后通过命令“请求当前位置补全”生成单行灰字；不会自动触发。

## 使用方式

1. 在设置的“手动补全”中启用功能，可配置排除文件或目录。
2. 在 Markdown 正文中放置单个光标，运行“请求当前位置补全”。可自行绑定快捷键。
3. 阅读灰字候选，按 Tab 插入，按 Esc 放弃；接受后可用一次撤销恢复原文。

输入、移动光标、切换文件、失焦或关闭功能会使旧候选失效。输入法组词、内置补全展开、多光标、代码、公式、属性及链接编辑等位置不支持此功能。原生 Windows 输入法及第三方补全插件组合仍需进一步验证。

## 费用与数据

固定使用付费 `deepseek-official / deepseek-flash`，不随聊天模型变化。发送当前标题（最多 200 字符）、光标前最多 3000 字符和后最多 1000 字符，不读取会话、记忆或关联笔记，不调用工具。上下文来自当前编辑器，可能包括尚未保存的内容。

每个库一次只能进行一个补全请求，间隔至少 2 秒，每分钟最多 10 次、每个 UTC 日最多 200 次；失败与取消同样消耗次数。这不是金额上限，也不汇总其他库或聊天费用。请求超过 8 秒会取消，不在应用层自动重试。

## 质量与验证

正式功能并不意味着内容必然正确。候选可能不符合语境、延续错误前提或产生错误事实，接受前需要阅读。没有可靠续写时可以不返回候选；格式异常、英文粘词、段落末悬空逗号和重复后文标点会被拒绝。

0.7 发布前增加真实博客文章挖空补全测试，使用原文副本构造输入，保持原文章不变。报告明确区分请求成功、候选可用、合理弃答和质量失败，不把模型输出与原文完全相同作为唯一标准。最新结果见 [0.7 验证记录](VALIDATION-0.7.0.md)。

早期开发过程、失败样例与当时的实验命名保留在 [历史记录](TAB-COMPLETION-EXPERIMENT.md)，不代表当前功能仍以实验渠道发布。
