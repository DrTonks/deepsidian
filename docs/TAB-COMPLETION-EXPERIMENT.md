# Tab 补全实验：手动灰字预览

本实验基于已提交的 0.6.5，分支为 `experimental-tab-completion`。首轮范围是 A+B：验证真实短请求，并提供手动触发、灰字预览和接受闭环；自动触发暂不实现。本文描述实验契约与验收方法，不代表以下检查已经通过。

## 使用与边界

功能默认关闭。开启后，在 Markdown 编辑器中运行“请求当前位置补全”命令；快捷键由用户自行绑定，避免与 macOS 输入法冲突。请求使用当前编辑器中尚未保存的光标前后正文，不加入聊天历史、长期记忆、全库搜索或工具调用。

- 灰字只是候选预览，接受前不写入文件或聊天记录。
- Tab 只接受当前仍然有效的候选；没有候选时保留编辑器原行为。
- Esc 拒绝候选并取消当前补全请求；没有补全时保留原行为。
- 输入、移动光标、切换文件、失去焦点或关闭功能时，旧结果失效；迟到结果不能插入。
- 中文输入法组词期间不发起补全，也不能用 Tab 接受候选。
- 接受通过单次编辑器事务插入，⌘Z / Ctrl+Z 应只撤销这次补全。
- 第一版只在适用的普通 Markdown 正文中插入短内容，不替换后文；多选区、代码、公式、属性区及链接编辑等位置暂不支持。

供应商固定为付费 `deepseek-official / deepseek-flash`，推理关闭，输出最多 128 token。笔记片段会发送给该供应商；没有合理续写时允许返回空内容，空返回不应制造提示性正文。初始化耗时与模型请求耗时分别记录，暖请求 deadline 为 8 秒。

## 请求限额与费用口径

手动补全也受限额：每个库最多一个在途补全请求，每分钟最多 10 次，每个 UTC 日最多 200 次。发出请求前计数，取消不退次数；日计数应持久化，重载插件不能重置额度。所有编辑器窗口共享本库额度。实验没有自动触发或应用层自动重试。

这些是本库的请求次数限制，不是供应商账户的精确金额上限，也不汇总其他库、其他设备或聊天的调用。供应商可能对已取消的请求计费；缺失 usage 时显示未知，不能按零计算。底层重试行为也必须纳入实现验收，不能仅因脚本没有重试便推断供应商只收到一次请求。

## 合成质量验证

`fixtures/completion-cases.json` 包含 20 个固定合成样例，覆盖中文半句、句中后文衔接、列表、引用、中英混排、标点、事实一致性及允许保守空返回的情况。样例不读取个人笔记。

以下命令会产生真实付费请求，由 DSH 读取本机凭证；串行运行，不重试。`--limit` 取固定集的前 N 例，不能把小样本当完整验收。

```sh
node scripts/live-completion.ts --limit=3
node scripts/live-completion.ts
```

报告存入 Git 忽略的 `.runs/live-completion-*`，包含：

- `report.json`：独立 cold start 耗时、每例暖请求耗时、候选/空返回/超时/错误、实际 usage 或未知，以及成功返回总体的 p50/p95。失败比例单列，不能用排除失败后的延迟宣称总体体验合格。
- `review.md`：每例前文、候选、后文及拼接后的完整正文，供人工逐例评阅。不会自动将空返回、错误、超时或仅返回文本称为质量通过。

人工评阅至少回答：能否直接插入？是否重复前后文或输出解释性前缀？Markdown 与标点是否连贯？是否有明显语义或事实错误？保守空返回是否合理？不要仅用字符串断言或接受率证明学习内容正确。变更提示词后复跑固定集，并补充少量此前未用于调优的样例。

实际试用的接受率定义为“接受次数 / 实际展示候选次数”；没有展示的过期结果、超时及错误另行统计。另记录接受后很快撤销的比例。合成批量脚本不能代替真实用户接受率，也不衡量编辑器灰字显示耗时。初始延迟目标是连接就绪后请求到可接受候选 p50 ≤ 1 秒、p95 ≤ 2.5 秒；这是目标，不是当前性能声明。

## 原生验收清单

1. 中文 IME 组词、提交、取消；Tab 不抢输入法或内置补全。
2. 普通段落、句中插入、列表与引用；实时预览及源码模式。
3. 延迟和乱序结果、切换文件、分屏、窗口切换、重命名、关闭插件；零过期插入。
4. Tab 原缩进行为、Esc 原行为、一次撤销、不改动已有后文。
5. 网络失败、取消、8 秒 deadline、限额耗尽、重启后的计数恢复。
6. 与内置链接补全及 Various Complements 共存；未经实测的插件组合不宣称兼容。
7. 停用实验并恢复稳定版后，聊天、草稿和设置仍可读取。

macOS 需要实机验证上述项目；Windows 原生中文 IME、Ctrl+Z 与 CRLF 文件目前待验收。CI 或浏览器组件通过不等于原生 IME 已验收。首次仅面向 macOS 隔离库的预览应如实标注平台验证范围。

## 构建、安装与回退

实验构建沿用 `deepsidian` 插件 ID，同一个库只安装一个版本；稳定版与实验版对照使用两个隔离库。实验只增加设置，不应迁移或重写聊天数据格式。安装说明应标注准确提交、实验版本及验证过的 DSH 版本。

在指定实验提交上安装依赖、检查并重新构建，然后再安装，避免复用旧 `dist`：

```sh
npm ci
npm run check
npm run install:dev -- "你的隔离测试库路径"
```

可安装包必须来自同一次构建，包含 `main.js`、`manifest.json`、`styles.css`、`bridge.mjs`、`THIRD-PARTY-NOTICES.txt`。`package:source` 是源码导出，会排除 `dist`，不能当可安装插件包。首个实验包只发布手动触发功能，不进入稳定版更新渠道。

回退时关闭插件，恢复同一插件目录中已验证稳定版的以上构建文件，再重新加载插件；保留当前 `data.json`，不要用实验前的数据备份覆盖它，以免丢失新增聊天。操作前可另存当前插件目录作备份。回退验收必须真实执行，不能只凭新增字段看似兼容便称已验证。

## 本次验证记录

2026-09-21，本地分支 `experimental-tab-completion`，基于 0.6.5 / `001d1de`，DSH 七组件 0.1.6-alpha.2。功能默认关闭，只有手动模式。manifest 保持基础版本 0.6.5，实验渠道通过分支及产物的 EXPERIMENT.txt 标明，不发布稳定版标签。

- 最终 `npm run check`：133 项离线测试、类型检查及构建通过。
- DSH 集成 12/12，通过真实本地合成服务验证两种协议、独立取消、并发聊天、超时、迟到确认、失败结束/截断拒绝、零自动重试及无持久补全会话。12 项集成在最后的英文边界校验前运行；该纯编辑器修订另有离线回归。
- 真实 EditorView 浏览器回归通过：灰字不进正文、Tab/Esc 让行与接受、单次撤销/重做、编辑与文件切换的迟到结果、组词事件、失焦、销毁。组词为合成事件，不代表原生中文输入法已经通过。
- 原生 macOS Obsidian 1.13.7，隔离库 `.runs/Mac 审查库`：设置中启用后，实际付费 flash 请求显示灰字；灰字显示期间检查磁盘正文未改变，Tab 接受后正文新增候选，⌘Z 一次恢复原文。另一次候选丢弃后正文未变。期间没有向供应商发送个人笔记。
- 原生回退验收：恢复已保存的稳定 0.6.5 程序文件、重载，补全命令消失；既有 5 个会话和草稿深比较保持一致。随后安装并重载最终实验构建。没有用旧 data.json 覆盖现有数据。稳定版若重新保存数据，可能丢弃它不认识的补全统计字段；切回实验版后统计可能重置，聊天不受该字段影响。

### 真实模型质量与延迟

共进行了两轮各 20 个固定合成样例和 4 个新增样例，另有原生 UI 请求，均使用付费官方 flash，无个人笔记。第一轮发现未知内容编造、次数与比例混淆，调整提示词并增加保守无候选标记；没有逐例硬编码答案。

第二轮报告 `.runs/live-completion-fJXnCv/report.json`：20/20 请求完成、无超时或错误，17 条候选、3 次无建议，usage 均返回。暖请求 p50 709 ms、p95 899 ms（仅本机这一小样本，包含无建议响应，不含冷启动）。根代理与独立子 agent 逐例评阅：16 条可直接插入，3 次合理放弃，1 条明确失败。此处为代理评阅，并非用户真实接受率或人工盲测。

明确失败例 `false-premise`：对“任意两个事件都是独立的”仍顺着补成概率乘积，不能宣称补全能可靠发现或纠正前文错误。接受候选前仍需要阅读，实验默认关闭，不以这一结果开放自动触发。

新增样例 `.runs/tab-holdout-45MTfT/report.json`：两个中文结果可用，一次未知测量合理放弃，一条英文输出缺少前导空格，会拼成 `isremoved`。已增加宿主边界校验与回归，遇到英文/数字无分隔拼接直接拒绝，不擅自添加空格；首版也不接受英文单词内部的补齐。付费脚本现在同时记录 rawText 和经过生产校验的候选，被拒绝候选单独计数。

### 尚未验收的范围

原生中文 IME 的完整组词流程（当前自动化尝试未能进入组词候选态）、Windows 原生 UI/IME、最低 Obsidian 版本、各种第三方补全插件、弹出窗口完整体验和长期使用接受率仍待验证。已经做了浏览器组合事件和迟到响应保护，但不将其写成上述平台的实机通过。

### 可安装实验产物

运行 `npm run package:experimental` 会重新构建，生成 `dist/tab-preview-<提交号>[-working]-<时间戳>/deepsidian/`。只包含程序文件和 EXPERIMENT.txt，不包含凭证、data.json、个人笔记或运行时历史。将该目录中的文件复制到隔离库 `.obsidian/plugins/deepsidian/`，启用后按本页说明测试。

## 发布后复审与分支命名

两位子 agent 复审编辑器与运行时路径，确认并修复两项 P2：同一行闭合的 `$$…$$` 会错误禁止后续段落补全；包含已闭合行内代码、链接或公式的普通正文会被整行排除。现在区分已闭合与仍在输入的结构，并遮蔽代码中的公式分隔符；未知语法树及未闭合结构仍拒绝。

修复后 135 项离线测试、类型检查与构建通过；运行时与宿主复审的 46 项测试通过，均使用本地合成供应商。本次没有新增付费请求或原生 UI 验收。

按用户要求，分支统一命名为 `experimental-tab-completion`。分支不使用工具名称前缀的约定保存于根目录 `AGENTS.md`，源码导出一并保留。
