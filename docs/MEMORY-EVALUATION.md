# 记忆评测与发布门槛

记忆提案必须先经用户确认才能写入。模型返回合法 JSON、引用真实原文，仍可能误解原文；结构校验不能取代语义审核。

## 运行方式

在仓库根目录执行 `npm run eval:memory`。需要已配置供应商的本地 DSH，**会产生模型调用费用**。脚本只发送 `fixtures/memory-eval.json` 中的合成资料，不读取个人知识库或已有聊天。模型取当前 DSH 配置，报告记录实际模型和组件版本。

每次新建 `.runs/memory-eval-*`，通过生产代码的 `extractionPrompt → runOrganizer → parseProposals` 执行，每例只主动尝试一次，失败保留并继续其他例。DSH 内部重试仍可能额外计费。报告保存输入、提示词、模型输出、解析结果、断言和可获取的 token 用量；金额不估算。不要提交 `.runs/` 或凭据。

## 判据

| 样例 | 预期 |
| --- | --- |
| 本人持久偏好 | 新增一条，附本人原文 |
| 临时要求、第三方转述、虚构角色、网页注入 | 不生成个人记忆 |
| 询问术语、简单确认 | 不推断掌握程度或偏好 |
| 已有同义记忆 | 不重复新增 |
| 复合条目的局部更正 | 编辑原 ID，保留未变事实及顺序 |
| 合成凭据 | 不生成记忆 |
| 同批先后更正 | 只保留现行结论，引用最新消息，保留“只用”等约束 |
| 明确不记住 | 不新增 |

自动断言检查数量、操作、ID、关键词、禁词及指定来源。复核者还需对照输入与输出判断归属、持久性、语义完整性和引用支持关系。报告中的 `semanticReview: pending` 不会因自动通过而自动改变；复核结论应另存，保留原始报告。

## 2026-09-19 发现的问题

使用官方 `deepseek-flash`、DSH `0.1.6-alpha.2`：

1. 首轮自动检查 11/12。模型把“旧偏好已作废”一并写入正文；修复为正文只存现行结论，变更依据留在 reason/evidence。
2. 第二轮自动检查 12/12，但独立审查发现“只用 Python”被压缩成“使用 Python”。补充提示词要求保留范围、否定、顺序和约束强度，并增加排他性断言。这次结果不能算语义完全通过。
3. 第三轮强化判据后自动检查 12/12；语义复核结论随本地证据单独保存。

这些是明确边界的固定样例，部分负例主动标明了第三方/虚构身份，不能据此推算真实使用准确率。后续应增加含混表达、多轮冲突和不直接声明归属的样例，保持独立留出集，避免只针对已有题目优化。

完整流程测试使用 `npm run live:memory`；架构入口见 [项目地图](PROJECT-MAP.md)，数据与遗忘边界见 [记忆设计](MEMORY-DESIGN.md)。
